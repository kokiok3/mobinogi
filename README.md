# 모비노기_[작성중]
### 후다🐔 보는 웹사이트

## 💬 소개
**모바일 마비노기의 사용자 랭킹 검색 웹사이트입니다.**  
전투력, 매력, 생활, 종합 랭킹에 대해 각 1000위 까지 검색할 수 있습니다.
각 랭킹은 서버 통합 랭킹을 보여줍니다.

## 기획의도
모바일 마비노기 공식 사이트에서 서버 통합 랭킹을 제공하지 않아서 서버 통합 랭킹이 궁금한 나와 같은 유저를 위해 만듦.
개발 시점에는 이미 3개 이상의 랭킹 사이트가 존재했지만, 그럼에도 개발하며 next.js를 숙지하고 배포까지 해보는 것을 목표로 했다.


## ✨ 주요 기능
-  **랭킹조회** - 서버 통합 랭킹 제공


## 🛠 기술 스택

| 분야 | 기술 |
|------|------|
| **언어** | TypeScript |
| **프론트엔드** | Next.js + Tailwind CSS |
| **백엔드** | Node.js + Express.js |
| **데이터베이스** | Redis |
| **호스팅** | Vercel (프론트) + Railway (백엔드) |


## 사전 요구사항
- Node.js 20 이상

## 이 프로젝트를 통해 배운점
크롤링, tailwind, nextjs, 모노레포, redis, docker, vercel, railway
* 크롤링:
  * 넥슨에서 제공하는 오픈 api가 있을거라 생각했는데 제공되는 오픈 api가 없어서 크롤링을 하게 되었다. html을 기반으로 크롤링해야했는데 공식사이트의 ui가 변경되면 크롤링이 깨질 수 밖에 없는 한계가 있어 아쉬웠다. 크롤링으로 전체 유저에 대한 랭킹 조회를 하기에는 부담이 커서 각 랭킹 당 1000명으로 제한했다.
  * 사이트에서 지속적인 요청을 막아서 최대한 사람처럼 크롤링 하는 방법을 구현해야 했다.
* 모노레포: 하나의 저장소에 클라이언트(랭킹 조회), 서버(크론, 크롤링, 데이터 저장), 공유 타입을 운영함.
  * 모노레포에 대한 개념
  * tsconfig.json, package.json을 통한 의존성 관리가 중요하기 때문에 각 설정에 대해 정확히 이해하는 것이 필요했다. 특히 서버 쪽 tsconfig.json에서 outdir, rootdir 를 처음에는 모노레포 내부 프로젝트 기준으로 했지만 rootdir가 전체 소스 코드를 포함해야한다고 해서 모노레포 최상단으로 해야 했다. 결국엔 중복되는 코드를 줄일 수 있어서 뿌듯했다.
* docker:
  * 조회성 명령어, 로그를 보고 디버깅 위주로만 경험이 있는데 dockerFile, docker-compose.yml로 직접 이미지와 컨테이너 생성을 해봄으로써 docker의 기본적인 실행 이론을 알게 되었다.
  * railway에서 dockerFile를 기반으로 배포를 하기 때문에 배포 전에 docker desktop에서 테스트를 실행한 뒤 배포를 진행했다.
* redis: 단순 조회성 데이터를 위해 조회 속도가 빠르고 적용이 비교적 쉬운 redis를 선택했다.
* next.js: csr 과 ssr 의 차이를 숙지하고 필요에 따라 어떤 프레임워크를 사용해야 하는지 공부함.
* tailwind: 적용이 쉽지만 코드가 길어져 가독성이 떨어진다고 생각되어 개인적으로 선호하지 않았다. 차라리 css in JS 가 JS 유저에게 더 다루기 쉬운 선택지 같다.
* vercel, railway: github 연동하여 쉽게 배포
